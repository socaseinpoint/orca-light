§ 01

Возвращаешься к коду — и ты потерян.You come back to the code — and you're lost.

Не помнишь почему принял решение, куда шёл, что уже сделано.You can't recall why you made the call, where you were headed, what is already done.

Харнес умеет в continuity — фоновые саммари, авто-память. Они реальные. Но это чёрный ящик: непроверяемая проза, непрозрачное хранилище, меняется под тобой без согласия.The harness does continuity — background summaries, auto-memory. They're real. But they're a black box: unverifiable prose, an opaque store, changing under you without consent.

Для работы, которой надо доверять, непроверяемое саммари дисквалифицировано. Это недоверие — и есть причина, почему orca существует.For work you have to trust, an unverifiable summary is disqualified. That distrust is exactly why orca exists.

§ 02

Три понятия. Состояние — это папка.Three concepts. State is a folder.

Уровни вычисляются из расположения, не объявляются флагом.Levels are derived from location, never declared by a flag.
focus

атом работыthe atom of work

Самодостаточная папка .orca/NN-name/: intent, done-when, Now, append-only Trail.A self-contained folder .orca/NN-name/: intent, done-when, Now, an append-only Trail.

ark

деливераблa deliverable

Конкретная штука под focus'ом, которую надо сдать. Тот же двухсостоянийный жизненный цикл.The concrete thing to ship under a focus. The same two-state lifecycle.

side-effect

результат вовнеthe result, outside

Реальный итог живёт вне orca — репо, Jira, SaaS. orca лишь указывает на него якорем.The real outcome lives outside orca — repo, Jira, SaaS. orca only points at it with an anchor.

Два состояния выражены расположением папки, не полем: in-work — .orca/NN/, done — .orca/done/NN/. Закрытие — это orca done, которое двигает папку, а не флипает статус.Two states are expressed by folder location, not a field: in-work — .orca/NN/, done — .orca/done/NN/. Closing is orca done, which moves the folder, not flips a status.

Граница — по проверяемости. done: авто-перепроверяет orca verify: коммит есть? файл ≥LINE? тест exit 0? why/next/head заякорить нельзя — это намерение — поэтому verify их игнорирует by design.The boundary runs along verifiability. done: is re-checked by orca verify: commit exists? file ≥LINE? test exit 0? why/next/head can't be anchored — it's intent — so verify ignores it by design.

§ 05

Continuity течёт сама. На входе — один resume.Continuity flows on its own. One resume on the way in.

d 01
orca trail — дописал блок: done с якорями + why/next/head.— append a block: done with anchors + why/next/head.
d 02
orca decide — неочевидное решение легло в decisions.md.— a non-obvious decision lands in decisions.md.
d 03
orca done — сдал деливерабл: двигает в done/ + пишет Log-строку.— ship a deliverable: moves to done/ + writes a Log line.
d 04
/orca-resume — субагент читает транскрипт прошлой сессии + git log, сжимает в один проверенный блок, выдаёт ре-ориентацию на один экран.— a subagent reads the prior transcript + git log, compresses into one verified block, hands you a one-screen re-orientation.

Под капотом resume live-aware и set-based: ledger сессий знает, какие транскрипты безопасно сворачивать — исключая текущую, живую параллельную, уже-свёрнутые и чужие проекты. Сворачивает множество ровно один раз, живой транскрипт не трогает.Under the hood resume is live-aware and set-based: a session ledger knows which transcripts are safe to fold — excluding the current one, a live parallel one, already-folded ones, and other projects. Folds the set exactly once, never touches a live transcript.
