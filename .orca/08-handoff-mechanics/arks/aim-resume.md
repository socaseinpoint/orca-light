# ark: aim-resume

focus: 08-handoff-mechanics
intent: make resume transfer AIM, not a menu. A session revs up to a coherent drive; a fresh session must be POINTED at the one hot focus + its single next action and START moving — not handed a flat list of old+new goals it can't orient in.
state: in-work
updated: 2026-06-04

## done-when
- resume identifies the recency-HOT focus (freshest Trail block / commit-time — derived on read, NO status field added; respects "views derived on read").
- with several in-work focuses, resume LEADS with the hot focus's `Now` + single `next:` and begins it (minimal confirmation), treating others as background/parked — not an equal fork.
- a flat fork is shown ONLY when genuinely ambiguous (two focuses equally fresh, or the hot one looks finished).
- guidance/skill change only — `bin/orca` untouched.

## context
This is the keystone ark — it fixes the exact "menu, not aim" problem these notes describe. orca keeps in-work focuses equal by design (no priority field); the cost is no aim transfer. Recency is the derived signal that restores aim without a status flip. Pairs with the close-nudge (already shipped) — both are the agent leading instead of waiting.
