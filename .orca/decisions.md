# decisions — orca-light

Why this repo's code is the way it is.
- 2026-06-04 — archive moves the ark to arks/archive/ instead of flipping a state: field — location is the single terminal truth (no two-store drift); live views already glob arks/*.md flat so archived arks drop out for free, and ls shows only live work
- 2026-06-04 — per-project resume is the spine; cross-project `now` is an opt-in lens on top, NOT the default. global itself was not the mistake — the mistake was putting the cross-project roll-up on the trust-critical path by default (which is what spawns ark-root/path-mangling/warn/the launch-dir seam). default resume should take the pwd repo with no mangling (no seam); the cross-project view becomes an explicit opt-in (`now --all`). keep the global binary; take the global registry off the hot path
- 2026-06-04 — resume fork (Step 1) MUST distinguish an ark-with-sessions (continue → compress prior transcript) from a thread-with-goal-but-no-ark (→ start new / init); presenting a bare thread as a continue-choice is a category error that made a doomlet pick thrash through report+find with nothing to compress — caught live dogfooding. this is also evidence for the per-project-spine decision: cross-project roll-up dumped a barely-setup other project onto the trust path; on per-project default doomlet would not appear without now --all
- 2026-06-04 — resume must compress the SET of uncompressed sessions since the last appended block, not just the single freshest prior transcript — N=1 is only a special case. boundary = mtime window after the last block (lightest; no new state vs recording folded transcript IDs). append one block per real session, oldest->newest, each anchored; skip empty/no-substance transcripts; and if nothing new since the last block (transcript+git both dry), append NO block (no confabulation). this subsumes the empty open+close trap: a throwaway session contributes zero and the real prior still gets folded
- 2026-06-04 — north star: orca exists to serve the user's GOAL — the measure of any design call is 'does it make the user's goal reachable, conveniently and clearly', not technical elegance. paired with the thread's 'lightest that works' as a productive tension: convenient+clear AND minimal. the test for any feature: does it make the goal reachable with the LEAST machinery? this is the LENS the other rebuild decisions are judged by (per-project default, fork ark-vs-thread, demux capture-all, report-as-overview all trace back to 'trustworthy AND clear for the human'), not just another item in the list. 'convenient' must not become a license to bloat
- 2026-06-04 — the original orca's inbox (surfaced-not-started arks + agent->user questions) is intentionally NOT reintroduced as a structure — it splits into two jobs both covered by existing primitives. (1) parked idea = a scaffolded ark with intent+done-when and zero session blocks (the doomlet case); requirement is that 'orca now' surfaces a 'not started' section, not a new file. (2) agent->user question = asked live via AskUserQuestion or parked in the handoff head/next, which persists because the ark persists. a dedicated persisted questions-queue only earns its keep IF orca ever goes async/unattended (background agents that hit a question while the human is away) — the current design forbids background, so it is YAGNI today. what must NOT be lost from the inbox is SALIENCE, not storage: 'orca now' must render parked arks and open questions un-missably. explicit trigger to revisit: orca adopting unattended/background agents
- 2026-06-04 — started PRINCIPLES.md as the curated home for standing design lenses, separate from the dated decisions ledger — a principle generates decisions, a decision is justified by them; mixing dilutes both. seeded with 7 already-earned: files-are-state, one-writer-per-file, meaning-in-dir+content-not-filename, trust-before-convenience, serve-the-goal-on-least-machinery, human-initiated-no-background, one-session-one-task. the filename principle now also rebuts tooling/dashboard cases: tools consume the registry+.orca/ topology+schema, not filename globs (4th time filename-encoding came up). one-session-one-task is load-bearing: a session maps to one ark by construction, defining away the cross-ark demux/attribution problem in decisions #4/#5 rather than solving it with machinery
- 2026-06-04 — orca should nudge the user toward correct use when a task looks done — if the ark's done-when is checkable and verify is green, suggest 'archive + start a fresh session' (surfaced via now/gate/Stop, reactive per human-initiated; silent when done-when is uncheckable, no false nags). rationale: one-session-one-task isn't only focus, it's compression fidelity — a small session transcript reconstructs with less loss at the resume squeeze
- 2026-06-04 — added principle #8 — orca teaches its own model: its surfaces (fork, now's where-you-stopped, red verify, done-when nudge) are didactic and steer the user to correct use rather than passively storing files; a human won't memorize the principles so the tool must embody them at point of use. rider: nudges must be earned (high precision, low frequency, reactive, silent when unsure) or alarm-fatigue trains the user to ignore all of them
- 2026-06-04 — the task-done nudge must bundle the runway: when orca recommends closing the session it also reminds where to pick up next — other open arks + parked (not-started) arks + any residual next: of the finished ark (a mini-now focused on what's left). closing is never a dead end; the user closes because the restart point is visible. serves #5 (clear, no fear of losing the thread) and #8 (teach correct use)
- 2026-06-04 — the close-runway and the next session's where-you-stopped reminder form a self-checking loop, consistent BY CONSTRUCTION because both derive from the same files (#1) — orca isn't storing a promise that could drift. close = prediction, open = fulfillment; the user watching them match earns trust and habit, same as verify earns trust on anchors (#4). emergent from #1 + the nudge, not new machinery
- 2026-06-04 — the close->open loop brackets every session (intro at open, outro at close, both in the transcript), which is an extra check FOR compression: the brackets give resume a frame (intent vs claims) instead of inferring from the middle, plus a self-check (block must agree with both ends), plus a context-fresh outro the compressor lifts+anchors rather than reinventing cold. design implication: the close-nudge summary should be in handoff shape (done/why/next/head + candidate anchors) so it seeds the next compression. not circular — verify grounds the brackets' anchors against reality, so an overclaiming outro still goes red
- 2026-06-04 — orca's model is sequential-per-ark; parallel sessions expose a resume defect. same-ark parallel is already forbidden by #2 (one writer). different-ark parallel is the real risk: resume picks prior = freshest non-current *.jsonl by mtime, so a LIVE session A's in-progress transcript gets grabbed by session B even though A is a different ark — silent partial compression + possible double block = quiet continuity corruption. fix tiered: (1) MIN/required — resume must detect a live/in-progress transcript (recent/growing mtime or a marker) and REFUSE rather than compress it partially (loud, not silent). (2) consolidated — record session context {ark, transcript-path, live-flag} at SessionStart, clear at Stop; ONE mechanism closes THREE holes: transcript-dir reconstruction (launch-dir seam), ark attribution (demux), and live-detection. discipline: parallel only on different arks
- 2026-06-04 — SUPERSEDES the earlier 'no recorded state; attribution = inference + human-confirm' lean. that lean assumed sequential sessions. the parallel-corruption risk is new evidence: when one small piece of recorded session-context (ark+transcript+live-flag at SessionStart) closes three holes INCLUDING a correctness/corruption one, the north-star calculus flips — it becomes the least machinery that makes the goal SAFELY reachable. 'lightest that works' must actually work; silent partial compression is not working. recording a fact at SessionStart is not background and does not violate #6
- 2026-06-04 — candidate: 'orca roadmap' = the FUTURE-tense view, completing a derived-view trio — report (past, cross-project timeline) / now (present, open arks + where you stopped) / roadmap (future, planned arks + order + deps + what's parallelizable). it is a missing VIEW, not a new subsystem: rendered on read (#1) from active arks + candidate arks (bare arks) + small optional content fields priority:/depends-on:|succeeds: (#3). its orca-specific value that Jira/TickTick cannot give: the ark-graph shows what is SAFE to parallelize (independent arks, no unmet deps, no live session) — ties to the parallel-corruption discussion. SCOPE GUARD (#5, anti-bloat): a view, not a PM engine — no due dates/assignees/sprints/status-workflow (orca is lifecycle-free; planning detail stays in the user's existing Jira/TickTick to avoid two sources of truth). NOT on the readiness critical path; a nice layer above MUST(session-context + live-aware refuse + ark-scope). parked as a candidate ark
- 2026-06-04 — the 'a session never gets compressed again' (loss) edge and the 'a session gets compressed twice' (duplicate-block) edge are the SAME root defect: current resume picks ONE freshest non-current transcript AND records nothing about what was already compressed, so the boundary is GUESSED and misses in both directions depending on timing (buried session -> lost narrative; stays-freshest session -> double block). neither #7 nor #16 alone fixes it: #7 (compress the SET of uncompressed-since-last, not one) + #16/#17 (record session-context: compressed-set / live-flag) are needed TOGETHER so each transcript is compressed exactly once. reassurance: nothing is truly gone even today — the transcript file stays on disk, code in git, design in decisions.md; worst case is narrative not auto-folded, still manually recoverable
